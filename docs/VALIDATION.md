# Validation evidence

Generated by `tools/make_demo.py`. Two kinds of evidence: the automated test suite, and the migration validation run on every fixture and every destination.

## Test suite

`python -m unittest discover -s tests -t .` at generation time:

```text
Ran 248 tests in 68.848s
OK
```

Areas covered (see the test files): object and nested-group resolution; ordered rules, implicit deny, ASA security levels and the interface-then-global order; stateful replies versus reverse initiation; stateless ACL return requirements and `established`; NAT address context; IPv6, UDP and ICMP; shadowed, redundant and conflicting rules; disabled rules; group aggregation that creates unintended access; unsupported applications, identities and schedules; hostile files and resource limits; the web server's access control; fuzzing with Hypothesis.

## Migration validation matrix (preserve workflow)

Each synthetic fixture is translated to each destination other than its own product, the destination text is parsed back with the destination adapter, and the source and the parsed destination are asked about the same sampled connections (one inside each rule, one just outside each address and port range, and a new connection from the server side).

Reading the table: *broader* means the destination permits a sampled connection the source denied. Cases explained by a known, reported cause (a stateless return rule that is broader by construction, or a source rule that was blocked) are separated from *unexplained* ones. *Narrower* means the destination blocks something the source allowed, typically a rule that could not be translated or a default behaviour that is not carried over. *Not compared* means an outcome could not be decided on one side (an unknown zone, an unresolved object, an application or schedule condition).

## What this evidence does not show

- Only the sampled connections listed below were compared; other traffic may behave differently.
- Both sides are evaluated by this tool's evaluator. A shared misunderstanding of a vendor's behaviour would not be caught.
- Applications, identities, schedules, security profiles, inspection, and the order of NAT versus filtering are not modelled.
- Connections that cannot be decided on either side (unknown zone, unresolved object, uncertain condition) are counted but not compared.
- Passing this check does not show the two policies are equivalent.
