# Changelog

## 0.1.0 (unreleased)

First working version.

* Security process (no change to the application): the test plan now follows the NIST SSDF and MITRE SAF, with a practice-by-practice self-assessment in docs/SECURITY_FRAMEWORKS.md. `tools/security_checks.py` also lists every suppression comment against a reviewed baseline and (optionally) converts the results with MITRE's SAF CLI. CI gains a weekly schedule, osv-scanner, zizmor, CodeQL, dependency review and OpenSSF Scorecard; Dependabot now also watches the pip files with a seven-day cooldown. SECURITY.md states response targets. Security checkpoint CP9 in `reports/cp9-security-framework/`.

* Named RuleTruss, with the OkieOTSec brand kit (shield, lockups, colour tokens, light and dark themes; contrast is tested).
* Example data: the Riverbend plant (three captures, a Zeek log, five device exports, subnets/labels/groups, and a guide whose every point is a test) and a small example; one-button loading; subnets, labels and groups can be loaded from and saved to JSON.
* Compare separates traffic that does not cross a device; a subnet's zone can list aliases (`outside|wan`) so one segment is named correctly for each product; subnets can be marked as outside your control, which drives external egress proposals.

* UniFi gateways (for example the Cloud Gateway Max): a zone-based firewall adapter reading the JSON written by `tools/unifi_export.py` (read-only calls to the gateway's local API, with a pinned certificate fingerprint and the key kept out of the command line), plus a guide, [docs/EXPORT_UNIFI.md](docs/EXPORT_UNIFI.md). Policies that only cover existing connections are never translated as permit rules. Not tested on a real gateway.
* Fuzzing with Atheris on the configuration, capture, Zeek and UniFi translation parsers (CP13) found and fixed four robustness bugs: a FortiOS `set` with no value, an ASA `access-list` line with no body, a network-object `subnet` with no mask, and infinite numbers in a Zeek log.
* UniFi to Cisco ASA translation redesigned after review: zone pairs are combined into per-network interface ACLs with each pair's destination scope kept (no more `permit/deny ip any any` from a pair default), correct per-pair ordering with External last, explicit handling of Gateway and VPN, a disposition and id for every source policy (also written into the output), impact statements for untranslated allows and blocks, a not-deployable preview banner with an export acknowledgement, source-zone inconsistencies reported without moving anything, MAC filters evaluated when the sender's MAC is known, and validation sampled per zone pair.
* Interface: an interactive graph (resizable, zoom and pan, drag, subnet clusters) with a drill-down panel for a device, a subnet or one direction, including a small sample of the traffic; a refreshed look (sticky header with icons, light/dark/system theme switch, clearer cards and tables); tabs that are not ready are marked and open a page that says what is missing; a UniFi example; `docs/TRAINING.md`, a generated training guide with labs, check questions and answers.
* UniFi evaluation corrected after studying a real export: connection states are matched and replies are checked in the reverse zone pair; every zone pair's final predefined Allow All / Block All policy is read as the default; the rule analysis no longer reports predefined policies as broad or conflicting (52 findings on a real 81-policy export became 9, all meaningful), is aware of connection states and ICMP types, and treats the ICMPv6 type of predefined policies (missing from the API) as unknown; addresses outside every network are placed in the External zone.
* Zone matrix on the Configuration tab for UniFi exports (source zone by destination zone, what each pair ends in, with a click-through to its policies in order); empty network, address and port filters are reported as undecidable instead of matching nothing or everything.
* Big captures: the size, packet, flow, time and memory limits can be raised at start-up (`--max-capture-mb`, `--max-packets`, `--max-flows`, `--parse-minutes`, `--parse-memory-gb`, each with a hard ceiling); files over 32 MB import in the background with progress and a Stop button; uploads are refused when the disk is nearly full; stored analyses may now be as large as the worker may return (they were capped lower, so a very large import could not be opened).
* Passive device identification: MAC addresses (ARP, DHCP, frames) with stated confidence, the card maker from the IEEE OUI listings (MA-L, MA-M, MA-S), which the user downloads on request with one button (the application's only opt-in network use; no IEEE data is shipped), randomised and shared MACs handled openly, and self-reported identity from LLDP, DHCP, SNMP, Modbus, EtherNet/IP, HTTP and SSH plus a weak TTL hint. Shown in the Devices table with a row detail, a shared-MAC list and a layer-2-only list; Devices CSV/Markdown exports; Riverbend guide points D01 to D07.

* Ingest: PCAP and PCAPNG (dpkt), Zeek conn.log; flows with initiation inference, confidence and evidence; application identification from payload structure with confirmed, probable and possible levels.
* Configuration adapters: Cisco ASA, Cisco IOS/IOS-XE ACLs, Palo Alto PAN-OS XML, Fortinet FortiOS CLI, pfSense/OPNsense config.xml.
* Vendor-neutral model with three kept-apart layers (observed, configured, proposed); three-valued evaluation; stateful and stateless behaviour; ASA interface, global and security-level behaviour; PAN-OS defaults.
* Explanations, inventory, subnet matrix, directional graph, observed-versus-configured comparison, shadowed/redundant/conflicting/broad rule analysis.
* Directional group policy worksheets (preserve and narrow workflows) with group aggregation, broadening and lost-restriction detection, and a separate external egress policy type.
* Firewall translation to Cisco ASA, Cisco IOS and FortiOS with blocked-not-widened semantics, return rules for stateless destinations, and round-trip validation on sampled connections.
* Local web application with a hardened loopback server, isolated parsing, private storage, deletion controls, CSV/Markdown/JSON exports, and an optional, off-by-default AI path.
* Security tooling and tests: hostile inputs, resource limits, fuzzing, server access control, SBOM, scan runner.
